## قاعدة البيانات والأمان

أُضيف **tasks فقط** إلى `smart_day_planner_newtech`، مع الحقول المطلوبة: id، user_id، title، description، task_date، start_time، end_time، priority، status، created_at، updated_at.

أُضيف عمود داخلي مولد `in_progress_date` وفهرس فريد `(user_id, in_progress_date)` لفرض مهمة In Progress واحدة لكل مستخدم/يوم. لا يظهر العمود الداخلي في API. توجد علاقة FK مع users باستخدام RESTRICT، وفهرسا بحث للتاريخ/الوقت والحالة/الأولوية، وقيود CHECK للعنوان وترتيب الوقت. جرى فحص وجود القيود والفهارس فعليًا في MySQL.

تأخذ عمليات الإضافة والتعديل والحذف قفل قراءة `FOR UPDATE` على سجل المستخدم داخل معاملة، دون تعديل بياناته. تُفحص التعارضات وتُحفظ المهمة ضمن المعاملة نفسها. الطلبات المتزامنة للمستخدم نفسه متسلسلة؛ فشلت محاولات تجاوز القواعد في اختبارات فعلية.

هوية المالك من الجلسة فقط. كل استعلام يقيّد المهمة بـuser_id الموثق؛ حقول الملكية المقدمة من العميل مرفوضة. قراءة أو تعديل أو حذف مهمة مستخدم آخر يعيد 404. بقيت حماية Origin وcookies وHttpOnly وSameSite وتجديد الجلسة وتشفير كلمات المرور كما كانت.

لم يُنفذ DROP أو TRUNCATE أو تعديل لسجلات مستخدمين موجودة قبل العمل. أظهر الفحص الأول 0 مستخدمين، ونُظفت حسابات ومهام وجلسات QA التي أنشأتها الاختبارات فقط. لم يُفتح أو يُعدّل مستودع الجامعة أو MADAR في هذه المرحلة.

## APIs والسلوك

| الطريقة | المسار | السلوك |
| --- | --- | --- |
| GET | `/api/tasks` و`/api/tasks/` | قائمة مهام المستخدم؛ فلاتر date وstatus وpriority اختيارية ومجتمعة |
| GET | `/api/tasks/:id` | قراءة مهمة يملكها المستخدم |
| POST | `/api/tasks` | إنشاء، HTTP 201 |
| PATCH | `/api/tasks/:id` | تعديل جزئي، HTTP 200 |
| DELETE | `/api/tasks/:id` | حذف، HTTP 204 |

كل المسارات تتطلب جلسة؛ الطلب غير الموثق يعيد 401 عند اجتياز فحص Origin للكتابة. المدخلات غير الصالحة تعيد 400 والتعارض يعيد 409، دون تغيير المهمة الأصلية.

العنوان 1–180 حرفًا بعد التشذيب، والوصف اختياري حتى 2000 حرف. التاريخ حقيقي بصيغة YYYY-MM-DD ضمن نطاق MySQL من 1000 إلى 9999، مع قواعد السنوات الكبيسة. الوقت HH:mm، وكلا الوقتين مطلوب للمهمة المؤقتة، والبداية قبل النهاية. المهمات غير المؤقتة مسموحة. تُرفض التداخلات عند الإنشاء أو تغيير الوقت أو التاريخ، وتُقبل الفترات المتجاورة. تستمر المهمة المكتملة في حجز وقتها وتبقى محفوظة. لا يوجد تغيير تلقائي للحالة أو جدولة تلقائية.

تُقرأ DATE/TIME كنص، ويُستخدم التاريخ المحلي للمتصفح كقيمة أولية؛ لا تُحوّل task_date إلى UTC. نقل الحالة بين Waiting وIn Progress وCompleted يدوي فقط.
